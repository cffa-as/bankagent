# bankagent 前端 skill

为 bankagent 生成或评审前端时，先把产品规则、视觉结构和状态边界说清楚，再写页面代码。当前仓库已有可运行的普通用户界面；新页面或交互仍需与既有文档、API 契约和动作状态保持一致。

## 技术基线

- 目标技术栈：Next.js + TypeScript strict。
- UI：优先使用已有项目依赖；没有现成组件库时，采用 Tailwind 和小型本地组件，不为几行样式新增依赖。
- 页面组件只负责展示和用户交互；风险、授权、MFA、执行、幂等和最终结果由服务端决定。
- 后续实现应保留可替换的 API 边界，不把演示数据、服务端逻辑或账户规则散落在页面组件里。
- 所有示例数据必须是合成数据；金额用最小货币单位进入业务契约，页面只负责格式化。

## 设计工作流

1. 读取 `AGENTS.md`、相关产品/技术方案文档和现有页面。列出受影响的页面、共享壳层、组件、API 契约、演示数据和测试。
2. 先写一页视觉计划：产品任务、用户、色板、字体、间距、布局线框、唯一记忆点和需要避免的默认风格。不要直接从“做一个现代后台”开始写代码。
3. 页面生成可以使用 Superdesign 做视觉探索、v0 做 Next.js 页面骨架，或使用 Codex 直接实现。工具生成的代码必须回到仓库规范中审查，不能因为生成器输出了代码就视为产品决策已确认。
4. 首次草案只覆盖一条核心任务链，优先展示：自然语言请求 → 服务端校验 → 黄色确认 / 红色 MFA → 执行回执。不要同时堆满所有功能。
5. 生成后检查截图或浏览器预览：信息层级、中文文案、键盘焦点、窄屏布局、`prefers-reduced-motion`、空态、失败态、过期态和错误提示。发现问题后做小范围修正，不无目的地继续生成变体。

## bankagent 视觉规则

- 视觉方向：安全控制台与私人银行终端的结合。冷白/铂金灰底、深海军蓝正文和壳层、克制的钴蓝作为交互强调、银灰结构线、平面表面、少量圆角和严谨留白。整体要像受监管金融机构的专业工作台，不像生活方式 SaaS、加密货币看板或黑客工具。
- 推荐字体：中文使用 Noto Sans SC / PingFang SC；英文和标题使用 Space Grotesk；金额、Trace ID、Action ID 使用 JetBrains Mono。
- 禁止默认套用紫色 AI 渐变、玻璃拟态、霓虹光晕、无意义的大圆角卡片、卡片套卡片、装饰性“AI 思考中”动画。
- 结构线、编号、标签必须表达信息。只有真的表示流程或步骤时才使用 `01 / 02 / 03`。
- 动画只响应用户动作或真实状态变化，默认 150–220ms；尊重 `prefers-reduced-motion`。不能用假进度代替真实服务端状态。
- 文案用用户听得懂的动词。按钮直接说明动作，例如“确认转账”“修改收款人”“验证并继续”；不写“提交”或空泛的“开始体验”。

## 金融安全界面规则

- 绿色查询：显示“查询 / 可直接查看”，可自动执行。
- 黄色动作：显示“需确认”，必须展示不可静默修改的动作快照、过期时间和明确的确认按钮。
- 红色动作：显示“需 MFA”，MFA 必须绑定 Action ID，不能设计成泛化的登录验证码。
- 状态颜色永远和文字、图标或形状一起使用，不能只靠颜色表达风险。
- 待确认状态不能显示交易成功、余额变化、收益或交易号。成功只能来自服务端业务回执。
- 页面需要能解释四件事：风险判定、动作快照、一次性执行门、审计记录。显示简短证据和状态即可，不展示模型思维链。
- 关键字段展示为快照行：收款人、金额、备注、风险、有效期、Action ID、Trace ID；变化必须进入新的动作确认流程。
- 取消、过期、MFA 失败、余额不足、工具失败和重复确认都要有可理解的页面状态。
- 网络重试必须复用同一逻辑操作的 `Idempotency-Key`；Action 与 Workflow 互相影响后要重新拉取双方状态，不能保留本地过期按钮。

## 生成提示词的固定骨架

给 v0、Superdesign 或其他生成器的提示词至少包含：

- 页面任务和目标用户；
- 明确技术栈（Next.js、TypeScript、Tailwind，如适用）；
- 视觉 tokens、字体和禁止项；
- 一条具体的用户任务链；
- 合成数据和页面状态；
- 服务端拥有最终裁决权的说明；
- 响应式、可访问性、键盘焦点和减少动画要求；
- 要求生成可运行的页面，不生成真实支付逻辑、密钥、真实账户数据或任意后端调用。

推荐开头：

> Build a polished Next.js + TypeScript page for bankagent, a Chinese-first secure AI banking workspace. Use the bankagent design tokens and show one complete user task. Treat all data as synthetic. The LLM may understand intent and prepare a plan; the server owns risk, authorization, MFA, execution, idempotency, audit, and the final receipt.

## 交付检查

- `git diff --check`。
- 文档/方案阶段：Markdown 链接和内容与现有安全边界一致。
- 前端实现阶段：`npm/pnpm` 的类型检查、lint、构建和受影响测试；涉及授权、MFA、幂等或状态机时补正向和负向用例。
- 生成代码中不得有真实密钥、Token、完整账户号、真实个人信息或绕过服务端裁决的假 API。
- 如果只是视觉草案，明确标注为草案，并给出预览或截图；不要声称已经接通业务。
