# bankagent 测试工程规范

## 分层准入

### 必须进入单元测试

- 风险阈值、日累计金额、余额和起购金额计算。
- 意图 Schema、实体校验、账单分类、异常规则和数据转换。
- 动作状态机、MFA 过期/重放/错误次数、幂等键判断。
- 生命周期 Trace、快照哈希、预约执行二次 MFA 和用户级熔断阈值。
- 预算持有到截止、收入未到账压力、Workflow 节点原子抢占、幂等落库降级和最终业务回执。

要求：零外部网络、零真实服务、优先表驱动、秒级完成。

### 进入集成测试或 E2E

- HTTP/API 协议、数据库事务、工具网关和账本协作。
- 查询 → 回执 → 审计。
- 黄色确认、红色 MFA、取消、过期、执行失败和重复提交主链路。
- 跨会话访问、权限隔离和人工接管边界。

E2E 只验证跨边界契约和主流程，不把内部算法复制一遍。

## 必须遵守的守卫

1. 不为普通参数变化复制同质用例；用表驱动或同一主流程覆盖输入矩阵。
2. 不用固定 `sleep` 证明并发顺序；使用锁、channel、barrier、事务或可控 fake。
3. Mock 只隔离外部系统，不 Mock 被测策略、状态机或执行门。
4. 内存数据库只验证常规数据流，不能证明生产数据库的并发锁和专有语义。
5. 负向用例必须覆盖：未授权、提示注入、字段篡改、MFA 重放、过期、重复确认、跨会话和工具失败。
6. 并发用例必须覆盖同 Action 重复确认、取消/确认竞争和不同幂等键竞争；断言只产生一次资金副作用。
7. 数据库故障用例必须验证资源与审计同事务回滚、幂等 pending/degraded 行为，以及资金回执不会在事务提交后补写。
8. 测试不能静默跳过缺少配置的安全路径；缺配置应明确失败或使用受控的本地 Fake。
9. 异步测试必须建立明确的 happens-before；收到 ACK 不代表所有派生状态已经发布。
10. 测试数据只用合成身份、账户和交易，不写入真实个人信息或凭据。

## 最小验收矩阵

| 能力 | 正向 | 负向 |
| --- | --- | --- |
| 绿色查询 | 返回工具数据并写审计 | 空数据不编造 |
| 黄色转账 | 确认后执行一次 | 未确认、篡改、重复确认不执行两次 |
| 红色转账 | MFA 通过后执行 | 错误、过期、重放、注入均拦截 |
| 理财申购 | 风险确认后返回委托回执 | 余额不足或未验证不改账本 |
| 状态控制 | 取消/过期进入终态 | 终态动作不能再次执行 |
| 会话隔离 | 只能访问自己的动作 | 跨会话读取或执行被拒绝 |

## 交付检查

- [ ] 说明测试属于单元、集成还是 E2E
- [ ] 核心规则和状态迁移有边界用例
- [ ] 权限和副作用有负向用例
- [ ] 并发测试没有用固定 sleep 证明成功
- [ ] 已执行最小相关测试，并记录未执行项
- [ ] 未把定向验证描述成全量通过
