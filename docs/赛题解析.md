# 赛题解析：银行 AI 智能体

> 文档类型：赛题要求与参赛理解
> 适用阶段：方案评审
> 关联文档：[竞品与参考实现](竞品与参考实现.md)、[技术方案](技术方案.md)

## 1. 赛题要解决什么问题

赛题要求构建一个银行 AI 智能体：用户通过自然语言描述金融需求，系统理解意图、规划任务，并在安全边界内完成银行业务操作。它的核心不是聊天，而是把对话可靠地连接到可授权、可审计、可中断的业务动作。

评审时需要同时证明三件事：模型能处理自然语言和多步骤任务；确定性服务能控制权限与风险；系统不会编造账户、交易或执行结果。

## 2. 赛题要求整理

### 2.1 场景方向

| 方向 | 示例能力 |
| --- | --- |
| 智能转账 | 按人名、手机号或备注转账；定时转账；AA 收款 |
| 账单分析 | 消费分类、异常交易、月度/年度报告 |
| 理财操作 | 产品推荐与对比、风险评估、申购/赎回 |
| 卡片管理 | 卡申请、额度、交易限制、挂失/解挂 |
| 订阅代扣 | 订阅识别、续费提醒、取消订阅 |
| 跨场景联动 | 预算锁定、生日提醒、定时采购等多步骤任务 |

至少覆盖三个核心场景，鼓励扩展到全部场景。

### 2.2 必须体现的技术能力

- 绿色：余额、流水、账单、收益等查询类操作自动执行。
- 黄色：小额转账、订阅取消、虚拟卡申请等展示详情并明确确认。
- 红色：大额转账、理财申购、密码及卡片高风险操作使用多因子验证。
- 防幻觉、防提示注入、关键操作审计、异常熔断和执行隔离。
- 支持模糊意图、上下文、省略信息、任务 DAG、中断、回退和人工接管。

赛题还要求提交作品简介、技术文档、答辩 PPT、演示视频、源代码及安全自评报告。

## 3. 方案取舍

### 3.1 首期覆盖

首期选择智能转账、账单分析、理财操作，原因是三个场景刚好覆盖绿色查询、黄色确认和红色强验证，并能展示“理解—授权—执行—审计”的完整闭环。

| 场景 | 首期验收重点 |
| --- | --- |
| 智能转账 | 金额与收款人抽取、日累计复核、黄色确认、红色 MFA、幂等和取消 |
| 账单分析 | 分类汇总、异常识别、数据可追溯、无数据不编造 |
| 理财操作 | 产品对比、风险提示、红色 MFA、余额与起购金额校验 |

### 3.2 首期边界

首期使用独立 Mock 银行账本，只演示可重复的模拟数据。暂不承诺真实银行核心系统、真实资金交易、生产级身份认证、人脸/短信/U 盾接入，也不提供大模型任意代码生成和执行。

卡片管理、订阅代扣、跨场景联动保留为后续扩展，不作为首期硬指标。若没有代码执行入口，沙箱要求应在安全自评中如实说明为“工具白名单和进程边界”；只有未来加入分析脚本或策略模拟时才启用独立进程/容器隔离。

## 4. 评审要看什么

1. 用户能否用一句话发起查询或业务动作，并在缺少关键信息时得到追问。
2. 权限是否由服务端规则决定，能否演示提示注入无法升权。
3. 黄色和红色动作是否有不可变详情、确认/MFA、有效期和一次性执行门。
4. 成功结果是否来自业务工具回执，失败是否明确说明账户未变化。
5. 取消、过期、重复提交、余额不足、验证码错误和并发执行是否可复现。
6. 一条 Trace 是否能还原输入、计划、策略、授权、工具回执和最终状态。

## 5. 建议的评审结论

先批准“安全内核 + 三个核心场景”的首期范围，待闭环稳定后再扩展卡片、订阅和跨场景联动。评审阶段只确认边界、架构和验收口径，不把建议方案表述为已经实现。
