# 赛题解析：银行 AI 智能体

> 文档类型：赛题要求与参赛理解
> 适用阶段：范围确认、实现核对与答辩评审
> 关联文档：[技术方案](技术方案.md)、[产品需求](产品需求.md)

## 1. 赛题要解决什么问题

赛题要求构建一个银行 AI 智能体：用户通过自然语言描述金融需求，系统理解意图、规划任务，并在安全边界内完成银行业务操作。它的核心不是聊天，而是把对话可靠地连接到可授权、可审计、可中断的业务动作。

评审时需要同时证明三件事：模型能处理自然语言和多步骤任务；确定性服务能控制权限与风险；系统不会编造账户、交易或执行结果。

## 2. 赛题要求整理

### 2.1 场景方向

| 方向 | 示例能力 |
| --- | --- |
| 智能转账 | 按人名、手机号或备注转账；定时转账；AA 收款 |
| 账单分析 | 消费分类、异常交易、月度/年度报告 |
| 理财操作 | 产品推荐与对比、风险评估、申购/赎回 |
| 卡片管理 | 卡申请、额度、交易限制、挂失/解挂 |
| 订阅代扣 | 订阅识别、续费提醒、取消订阅 |
| 跨场景联动 | 预算锁定、生日提醒、定时采购等多步骤任务 |

本项目目标是覆盖全部六个核心场景，统一验证查询、确认、强验证和跨场景编排能力。

### 2.2 必须体现的技术能力

- 绿色：余额、流水、账单、收益等查询类操作自动执行。
- 黄色：小额转账、订阅取消、虚拟卡申请等展示详情并明确确认。
- 红色：大额转账、理财申购、密码及卡片高风险操作使用多因子验证。
- 防幻觉、防提示注入、关键操作审计、异常熔断和执行隔离。
- 支持模糊意图、上下文、省略信息、任务 DAG、中断、回退和人工接管。

赛题还要求提交作品简介、技术文档、答辩 PPT、演示视频、源代码及安全自评报告。

## 3. 方案取舍

### 3.1 首期覆盖

六个场景全部纳入实现范围：智能转账、账单分析、理财操作、卡片管理、订阅代扣和跨场景联动。六个场景共同覆盖查询、确认、强验证、定时任务、外部服务调用和多步骤编排。

| 场景 | 首期验收重点 |
| --- | --- |
| 智能转账 | 金额与收款人抽取、日累计复核、黄色确认、红色 MFA、幂等和取消 |
| 账单分析 | 分类汇总、异常识别、数据可追溯、无数据不编造 |
| 理财操作 | 产品对比、风险提示、红色 MFA、余额与起购金额校验 |
| 卡片管理 | 状态与额度查询、虚拟卡申请、冻结/解挂、额度变更和回执 |
| 订阅代扣 | 订阅识别、续费提醒、黄色取消、历史交易保留 |
| 跨场景联动 | 预算锁定、提醒、采购订单、有限 DAG、失败停止后续副作用 |

### 3.2 首期边界

项目使用独立账本和合成数据，覆盖竞赛要求的六类银行业务。模型不生成或执行任意代码，安全边界按工具白名单和进程隔离实现。

## 4. 评审要看什么

1. 用户能否用一句话发起查询或业务动作，并在缺少关键信息时得到追问。
2. 权限是否由服务端规则决定，能否演示提示注入无法升权。
3. 黄色和红色动作是否有不可变详情、确认/MFA、有效期和一次性执行门。
4. 成功结果是否来自业务工具回执，失败是否明确说明账户未变化。
5. 取消、过期、重复提交、余额不足、验证码错误和并发执行是否可复现。
6. 一条 Trace 是否能还原输入、计划、策略、授权、工具回执和最终状态。

## 5. 参考项目与采用结论

本项目只保留能落到安全内核和演示链路的参考经验：

| 参考对象 | 借鉴 | 不直接采用 |
| --- | --- | --- |
| Revolut AIR | 单一对话入口连接消费洞察、投资、订阅和卡片能力；敏感操作需要用户批准 | 公开资料未披露其内部模型、风控和交易实现 |
| OpenClaw | 会话路由、运行控制、审批、中断和人工接管 | 审计日志不能替代授权证据或业务回执 |
| xrobotd | Session/Turn、工具 Schema、Trace、取消和单一仲裁入口 | 设备、语音、WebSocket、Manager 拓扑和设备 MCP |
| LangGraph / Temporal | 持久化运行、暂停恢复和人工介入的思路 | 首期 Go 单体不引入 Python 运行时或完整工作流平台 |

最终采用 Banking Agent Core：模型只负责意图、实体和候选计划；Go 服务端负责策略、授权、动作状态、执行门、账本事务和最终结果；MCP 只负责受控工具协议。首期不引入通用多 Agent、任意代码执行或插件市场。

参考资料：Revolut AIR 官方介绍、OpenClaw Agent runtime/session 文档、LangGraph 官方文档、OpenAI Agents SDK 文档，以及本机 xrobotd 的 `AGENTS.md` 和 Agent/Turn 实现。

## 6. 当前完成度与评审结论

普通用户版本已完成六个场景的主链路：

1. Action 状态机、幂等、MFA 锁定、一次性执行门和日累计执行前复核。
2. 姓名/手机号转账、定时转账、AA 拆分，以及账本回执。
3. 月度/年度账单、分类占比、可解释异常和订阅续费提醒。
4. 理财申购/赎回、收益计算、卡片状态/额度/挂失和订阅取消。
5. 有限 DAG、`due_at`、虚拟时间推进、真实预算占用和订单消费锁定额度。
6. 审计链、提示注入边界、取消竞争、跨会话访问隔离和负向集成测试。

代码、接口、测试、核心设计文档和作品简介已经达到当前评审范围。30 秒品牌片与 3:02 完整业务演示均已生成；答辩 PPT 按当前安排暂缓。
