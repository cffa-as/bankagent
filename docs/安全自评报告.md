# bankagent 安全自评报告

> 版本：v0.2 · 适用范围：比赛演示版 · 数据范围：本地演示账本

## 1. 结论

当前实现可以在本地演示环境完成“自然语言请求 → 服务端动作 → 黄色确认或红色 MFA → 业务回执”的安全链路。生产级外部接入不在当前范围。

## 2. 控制项自评

| 控制项 | 当前实现 | 证据/限制 |
| --- | --- | --- |
| 权限分级 | 已实现 | 绿色查询自动执行；黄色动作确认；红色动作绑定 MFA。规则在 Go 服务端。 |
| 动作快照 | 已实现 | 金额、收款人、产品和有效期随 Action 保存；SHA-256 快照哈希在授权和执行前复核。 |
| 幂等 | 已实现 | 副作用请求要求 `Idempotency-Key`；执行前原子预留，成功响应固化，相同键复用结果。 |
| 一次性执行门 | 已实现 | 动作状态和 SQLite 条件更新共同控制确认/MFA 与执行竞争。 |
| MFA | 演示实现 | 固定演示验证器，错误 3 次锁定 Action；红色预约执行时重新发起 MFA。 |
| 审计 | 已实现 | Action 全生命周期共用 Trace；动作创建和状态迁移审计与业务写入同事务，确认/MFA 成功和结果均有事件。 |
| 提示注入防御 | 已实现基础控制 | 模型只输出候选计划；工具白名单、Schema、风险和授权不受用户 Prompt 改写。 |
| 结果防幻觉 | 已实现 | 成功状态来自业务工具回执；前端不乐观宣称成功。 |
| 对话上下文 | 演示实现 | 保存最近用户消息，仅 30 分钟内最近 6 条用于追问补全；读取按会话和用户隔离，尚未实现生产级留存/删除策略。 |
| 日累计复核 | 已实现 | 黄色转账在确认/触发时再次读取当日流水，超过 1000 元会失败并要求重新发起。 |
| 预约动作 | 演示实现 | 授权后进入 `scheduled`，到点显式 trigger；红色动作生成新的执行 MFA，之后仍经过状态、幂等和日累计复核。 |
| 预算锁定 | 已实现 | `reserved_minor` 占用可用余额；预算型 Workflow 保持占用到截止、取消或订单消费，订单只能消费已锁定额度。 |
| 流动性预检 | 已实现 | Go 按事件流计算四种情景；最大建议预算同时满足预期、保守和收入未到账情景，最长覆盖 366 天。 |
| 异常熔断 | 已实现 | MFA 错误先锁定 Action；同一用户 10 分钟内累计 6 次失败或可疑输入会触发 15 分钟写操作锁定，查询保持可用。 |
| 代码执行隔离 | 未启用 | 系统不允许模型生成或执行任意代码，因此没有脚本执行入口。 |
| 数据隔离 | 演示级 | 服务端校验 Demo 用户和资源归属；仅使用本地合成数据。 |
| Run 控制 | 已实现 | Run 持久化支持停止、人工接管和撤销待执行动作；已执行动作不会被静默冲正，统一进入人工复核。 |
| APP / IM 渠道适配 | 演示实现 | 提供受控渠道消息入口并复用同一 Agent；当前不包含企微/飞书等平台原始 Webhook 验签，终端身份必须由渠道网关完成。 |

## 3. 已知风险

1. Demo Token 是固定演示身份，不能用于生产认证。
2. SQLite 适合单机/单实例演示；没有多实例高可用、密钥托管和灾备能力。
3. 独立 MCP Server 当前未实现；六场景由 Go 服务端白名单领域工具直接执行。跨进程部署时必须补服务间认证、Schema 校验、超时、对账和监控。
4. 跨场景 Workflow 使用显式 `advance`/`virtual_now` 推进，没有常驻后台调度器；进程退出期间不会自动执行预约任务。
5. AA 拆分只登记收款请求，不向其他参与人扣款；鲜花/蛋糕订单不连接外部商户。
6. 理财收益按固定产品规则计算，不构成收益承诺。
7. 汇率、真实风控评分、真实适当性评估和交易对账尚未接入。
8. 查询和补充授权事件在业务提交后追加；Action 创建与状态迁移由 SQLite 触发器同事务记录。外部审计消费者或告警系统尚未接入。
9. 当前副作用在本地 SQLite 中同步完成，`reconciliation_required` 尚未接入远程工具超时/未知回执链路。
10. 流动性预检是基于预置现金流和历史消费的 what-if 结果，不构成未来余额保证或投资建议。
11. 幂等最终响应落库失败时会保留 pending 记录并返回原业务结果，响应头标记 `degraded`；该 key 不会自动恢复，需要后续补偿或运维排查。
12. APP/IM 当前是银行侧渠道适配入口，未接入具体平台开发者凭据、Webhook 验签或消息加密。

## 4. 发布前必须补充

- 接入真实身份、设备绑定、MFA 和密钥托管方案。
- 若启用远程工具，补 mTLS/Bearer Token、Schema 校验、超时、对账和告警。
- 做并发、故障注入、依赖升级和第三方安全测试。
- 对所有敏感字段执行脱敏、加密、留存和删除策略评审。
