# 竞品与参考实现

> 调研目的：提炼能落到 bankagent 的产品和工程经验，避免堆砌框架。
> 调研日期：2026-10-31

## 1. Revolut AIR

Revolut 官方在 2026 年 4 月 9 日发布 AIR（AI by Revolut），并从英国开始逐步推送。公开介绍显示，AIR 被嵌入手机银行，用对话完成消费洞察、投资信息查询、订阅管理、卡片冻结、卡片控制和旅行相关服务；官方还强调只访问用户在应用中本来可见的数据、第三方零数据保留，以及敏感操作需要生物识别批准。

参考：

- [Revolut 官方发布说明](https://www.revolut.com/news/revolut_enters_new_era_of_money_intelligence_with_launch_of_ai_assistant/)
- [AIR 产品介绍](https://www.revolut.com/blog/post/air-ai-by-revolut/)

对 bankagent 的启发是“单一对话入口连接多个金融动作”，而不是照搬其具体产品、认证系统或真实交易能力。AIR 的公开页面不能证明其内部模型、工具编排或风控实现，因此本方案只把公开能力作为产品对标，不把未知实现写成技术依据。

## 2. OpenClaw

OpenClaw 适合作为控制面和运行时的参考：渠道接入、会话路由、运行身份、工具事件、审批、中断和人工接管可以分层管理。它提醒我们把一次运行、一次动作和一次业务回执区分开，并让不同用户、群组或会话保持隔离。

需要保留的限制判断：审计记录可能是 best-effort，审计日志本身不能证明授权，也不能替代银行工具或外部业务系统的成功回执。因此 bankagent 要把授权证据、审计事件和业务回执分别建模。

参考：

- [Agent runtime architecture](https://docs.openclaw.ai/agent-runtime-architecture.md)
- [Gateway audit](https://docs.openclaw.ai/gateway/audit.md)
- [Session](https://docs.openclaw.ai/concepts/session.md)

## 3. 本机 xrobot

本机 `/Users/chenfeifan/xrobot/xrobotd` 的 `AGENTS.md`、测试工程 skill 和 Agent/turn 相关实现可作为工程约束参考。最值得复用的是这些原则：

- 外部输入在边界统一校验；工具参数经过 Schema 校验后才能执行。
- 确认、取消和副作用启动放在可竞争的状态边界内，只允许一个结果获胜。
- 被取消、过期或被替代的任务不能继续调用工具；重复确认必须幂等。
- 模型输出不是授权，确认/MFA 只有一个权威入口。
- Trace 限制深度、数量和文本长度，敏感字段脱敏；审计失败要告警但不能伪造成功。
- 单测离线、秒级、优先表驱动；E2E 只验证跨服务协议和主链路，不把业务算法重复堆到 E2E。

这些原则适合转成 bankagent 的动作状态机、执行门、审计字段和测试分层。xrobot 的 Go、设备、语音、MCP 以及服务拓扑与本项目无关，不直接复制。

## 4. bankagent 的采用结论

首期只采用四个共同结论：

1. 用轻量控制面管理会话、动作、审批、中断和审计。
2. 用 LLM 处理意图和候选计划，用确定性策略计算风险和授权。
3. 用不可变动作快照、幂等键和一次性执行门保护资金类副作用。
4. 用 Mock 业务工具提供唯一的成功/失败回执，用结构化结果渲染最终回答。

首期不引入大型 Agent 框架、任意代码执行、无关平台能力或“模型直接调用高风险工具”的设计。待评审通过后，再根据真实实现复杂度决定是否需要引入图编排库。
